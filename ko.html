SO-ARM101로 SmolVLA 픽앤플레이스

카메라 두 대를 장착한 SO-ARM101이 물체 두 개를 접시에 옮기도록 SmolVLA(비전-언어-행동 정책)를 파인튜닝했습니다. 시연 데이터는 텔레오퍼레이션으로 직접 수집했고, 학습은 노트북 GPU에서 진행했습니다. 사전에 정한 평가 절차에 따라 실제 로봇팔에서 20회 평가했습니다.

60k학습 스텝(약 21 에폭). 초기 학습은 에폭 부족
79텔레오퍼레이션 에피소드, 57,519 프레임
  1. 학습 설정 비교 실험. 학습률, 배치 크기, 스텝 수를 하나씩 바꿔 비교했습니다. 동일한 3.48 에폭에서 최종 loss는 lr 1e-5가 0.187, 1e-4가 0.089였으므로 1e-4로 복귀했습니다. 20k 스텝 run 두 개는 전체의 71–72% 지점에서 loss가 정체되었으나, 60k run은 해당 지점 이후에도 0.022까지 감소했습니다. 병목은 하이퍼파라미터가 아니라 학습량(에폭)이었습니다.
    Run최대 LR에폭Loss성공
    b4 · 20k1e-41.390.111—
    b8 · 20k*1e-42.900.088—
    b20 · 10k1e-53.480.1870/2
    b20 · 60k1e-420.860.0222/20
    배치 · 스텝. cosine decay, warmup 1,000 스텝(b8은 666). Loss는 train loss의 마지막 1,000 스텝 평균. *다른 데이터셋 사용(55,129 프레임). 나머지는 79 에피소드 데이터셋.
  2. 실패 원인 분석. 실패 18건 중 11건이 그리퍼 위치 오류였습니다. 파지에 실패했거나 집게가 물체 위에 얹힌 경우입니다.
  3. 인지 지연. 파지에 실패한 뒤에도 빈 그리퍼를 접시까지 옮기는 현상이 있었습니다. 50스텝 청크 하나를 생성하는 데 약 1.9초가 걸리며, 그동안 팔은 정지합니다. 이후 약 1.9초 동안은 장면을 다시 관측하지 않고 청크를 그대로 재생합니다. 즉 약 3.8초에 한 번만 장면을 관측하므로 제어 루프가 26 Hz가 아닌 13 Hz로 동작했고, 파지 실패는 다음 관측 시점에야 반영됩니다.
  4. 샘플링 노이즈 검증. 판단 시점마다 정책을 오프라인으로 32회씩 재샘플링했습니다. 첫 판단을 제외하면 샘플이 좁은 범위에 집중되어, 실패가 샘플링의 우연에 의한 것이 아님을 확인했습니다.

DECEPTACON: 아르마딜로처럼 구형으로 변형되는 로봇

구형 상태에서 다리 네 개를 펼쳐 보행하는 로봇을 팀 프로젝트로 제작했습니다. 제 담당은 기구 설계 및 제작이었습니다. CAD와 3D 프린팅 전반, 출력 품질·공차 시험, 베어링 배치를 맡았으며 전장은 팀원들이 담당했습니다.

  1. V1 다리: Servobot 방식에 다리 수납용 관절을 추가한 구조. 모터까지 다리와 함께 외부로 전개되어야 해서 부피가 과도했습니다.
  2. V2 다리: 외피 패널을 그대로 다리로 사용하고, 서보 하나로 패널을 외부로 전개합니다. 다리당 서보 수를 3개에서 2개로 줄였습니다.
  3. 보행 중 파손: 보행 중에 베어링을 받치던 출력 로드가 파손되었습니다. 금속 볼트와 스페이서로 교체했으나 이번에는 베어링이 이탈했습니다.
  4. 교훈: 출력 로드로는 베어링 하중을 견딜 수 없습니다. 베어링은 고정형 하우징에 안착시키고, 몸체 전체를 출력하기 전에 다리 하나로 보행 하중 시험을 먼저 해야 합니다.

STS3215 서보 드라이버: 버스 프로토콜부터 직접 구현

SO-ARM101은 Feetech STS3215 시리얼 버스 서보로 구동됩니다. 제조사 SDK 없이 패킷 구성, 체크섬, 레지스터 맵, 단위 변환까지 드라이버를 직접 구현했습니다. 하나의 핵심 라이브러리를 Windows 시리얼 백엔드와 Arduino IDE에서 공용으로 사용합니다.

  1. 플랫폼 독립성: g++와 Arduino 툴체인 모두에서 컴파일되는 순수 C++11 코어. 플랫폼별 입출력은 단일 백엔드로 분리했습니다.
  2. 하드웨어 없는 테스트: 가상 버스로 패킷 송신의 정확성을 검증합니다.
  3. 실물 검증: 실제 서보에서 ping, 위치 읽기·쓰기가 동작합니다. Uno 데모에서는 16×2 LCD 메뉴, 버튼, 가변저항으로 서보를 제어합니다.
  4. 추후 작업: 오류 처리, 다중 서보 읽기 속도 측정, Uno 단독 구동 조이스틱 IK.

BagelEngine: 직접 개발한 Vulkan 엔진

2023년 11월부터 개발 중인 3D 엔진입니다. 배치 렌더링과 ECS에서 출발해 PBR, 물리, 절차적 월드 생성까지 구현했습니다. 단계별 개발 일지를 GitHub 위키에 기록하고 있으며, 현재 30편입니다.

  1. 렌더러: 바인드리스 디스크립터, 인다이렉트·인스턴스 드로우, 세컨더리 커맨드 버퍼, 노멀 맵을 쓰는 PBR, 캐스케이드 섀도, 블룸, SMAA.
  2. 데이터 지향 코어: EnTT 컴포넌트를 연속 메모리에 배치해 캐시 친화적으로 순회합니다. 물리는 Jolt.
  3. 콘텐츠: 스켈레탈 애니메이션을 지원하는 glTF 로더, YAML 씬 파일, 노이즈 레이어 합성 방식의 절차적 행성 생성기.
  4. 툴링: 엔진 내장 콘솔과 MCP 서버 연동 원격 콘솔. 에이전트가 엔진을 조작하고 스크린샷을 촬영할 수 있으며, 이 페이지의 엔진 스크린샷도 이 방식으로 촬영했습니다.
